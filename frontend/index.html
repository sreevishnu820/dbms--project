What is Linear Probing?

              
A collision resolution technique in open-address hashing. Experiment interactively
                below.

            

          

          

            

              Linear probing is an open-addressing strategy for handling hash
                collisions.
              When two keys map to the same slot in the hash table, instead of chaining, we look for the
              next available (empty) slot by moving forward one step at a time through the table —
              wrapping around to the beginning if needed. This keeps all data inside the main array and is
              cache-friendly, but can suffer from primary clustering if the load factor grows too high.
            

            

              

                
 Hash Function

                
The home slot for a key k with table size m is computed as:

                
h(k) = k mod m

              

              

                
 Probing Sequence

                
If slot h(k) is occupied, try consecutive slots:

                
(h(k) + i) mod m, i = 0, 1, 2, ...

              

              

                
 Collision

                
A collision occurs when h(k₁) = h(k₂) for two different keys. Linear probing resolves it by
                  probing the next slot linearly.

              

              

                
 Primary Clustering

                
Long consecutive occupied runs form clusters, increasing average probe length. Keeping the load
                  factor α < 0.7 avoids this problem.

Deletion & the Tombstone Problem

            

          

          

            
Deleting a key in linear probing is tricky. Simply marking a slot as empty (EMPTY) breaks the
              probe chain for any later-inserted key that passed through that slot. The standard solution is to mark
              deleted slots with a special DELETED sentinel (also called a tombstone).

            
Tombstone slots are treated as occupied during a search probe (the probe continues past
              them), but as empty during an insertion probe (a new key can fill them). This simulator
              marks deleted slots with DEL so you can
              observe the behaviour.

            
Insert: stop at first EMPTY or DELETED slot
Search: stop
              only at first EMPTY slot (DELETED does not break the chain)

Using the query workspace

              
Classify SQL commands, understand each category, and download a report of your
                results.

            

          

          

            

              

                

                  
Enter SQL commands

                  
Type or paste one or more commands into the editor. Separate multiple commands with a semicolon
                    (;). Comments starting with -- are ignored.

                

              

              

                

                  
Execute and classify

                  
Select Execute & classify or press Ctrl + Enter.
                    Each statement is checked against standard SQL syntax and labelled DDL, DML, DQL, DCL, TCL, or
                    flagged as a syntax error.

                

              

              

                

                  
Review the results

                  
Open any result to see its keyword, purpose, database effect, analysis, and a ready-to-run Python
                    snippet. Select a category tile to filter by DDL, DML, DQL, DCL, or TCL. Recent queries are saved so
                    you can reload them.

                

              

              

                

                  
Download the report

                  
After a run, select Download report to save a text file with the commands,
                    classifications, counts, and timestamp.

                      Table to apply.
